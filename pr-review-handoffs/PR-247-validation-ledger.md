## Working contract

1. Validate one finding vertically before starting the next: impact → test → observed failure → reachability → verdict.
2. A behavior defect present at HEAD gets a test for the desired contract that is RED at HEAD.
3. A missing regression pin, such as C1, gets a test that is GREEN at HEAD and RED against the smallest mutation that removes the promised behavior.
4. Documentation drift, dead code, and structural duplication are not forced into artificial RED tests. They receive inspection evidence or an isolated POC.
5. Validation tests must use a public service/protocol boundary and deterministic fakes or Testcontainers. No sleeps as synchronization, Mockito verification, reflection, or widened production visibility.
6. A RED test is retained only when it is safe for the normal suite. Tests proving a current defect stay in `pr-review-handoffs/validation-tests/` until the fix exists; mutation-killing tests may join `src/test` immediately.
7. Every LOC claim is measured from a throwaway diff. A POC succeeds only if behavior stays green, actual LOC falls, the module interface gets no wider, and the result is easier to navigate. Otherwise it is recorded as a failed experiment and discarded.

= ADR 0026: Expected Mutation Rejections Use Typed GraphQL Outcomes

== Status

Accepted

== Context

Administration mutations have expected business rejections such as a missing reason, restricted Account, or last-admin invariant.
Returning those outcomes as untyped top-level GraphQL errors makes clients parse messages and obscures the difference between a rejected operation and a failed request surface.
Some invariants are enforced by PostgreSQL and are observable only after the write is attempted.

== Decision

Application services return protocol-agnostic `Outcome` values for accepted operations and expected business rejections.
GraphQL mutation adapters translate those values into schema-defined payload unions and typed `userErrors`.
Authentication failure, whole-surface authorization failure, authorization unavailability, and unexpected infrastructure failure remain top-level GraphQL errors.

Services authorize before mutating and perform the mutation inside `MutationTransactions`.
Database constraint violations are translated by stable constraint name after the transaction has rolled back, including names exposed through Hibernate and the PostgreSQL driver.
Unknown constraint violations are not converted into business outcomes.
Concurrent conditional transitions create an audit event only for the transaction that changes state.

Mutations and visibility checks follow the not-found oracle from ADR 0024: a caller that cannot observe a resource receives the same result as if it did not exist.
Resolver tests verify protocol translation and cursor behavior; service tests verify the use-case contract; PostgreSQL integration tests verify constraints, transactions, and races.

== Consequences

* Clients can exhaustively handle expected mutation outcomes without parsing human-readable messages.
* Database-enforced invariants remain the concurrency authority while still producing stable client-facing errors.
* Rollback completes before translation, so a rejected mutation cannot leave a partial write or audit record.
* New expected rejections require coordinated application outcomes, schema types, adapter mappings, and tests.

== Rejected Alternatives

* Returning every rejection as a top-level GraphQL error — clients lose typed, mutation-local outcomes.
* Translating violations by database message text — messages are unstable across database and driver versions.
* Prechecking every invariant in Java — check-then-act races can violate the invariant under concurrent writes.

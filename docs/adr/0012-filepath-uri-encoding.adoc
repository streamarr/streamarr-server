= ADR 0012: Filepath URI Encoding

== Status

Accepted

== Context

The codebase had two representations for filesystem paths: `MediaFile.filepathUri` stored URI-encoded strings (`file:///media/Alien%C2%B3.mkv`) while `Library.filepath` stored plain strings (`/media/movies`).Frontend consumers would have to handle each field differently, and plain strings silently broke on non-ASCII characters (e.g. accented titles, CJK).

`Image.path` is a separate concern.Images are served via `/api/images/+{id}+`.

== Decision

All filesystem paths persisted in the database use `file:///` URI encoding via `FilepathCodec`.
Fields that reference the local filesystem are named `filepathUri` to signal the encoding.
Fields that hold server-relative resource identifiers served by our API (e.g. `Image.path`) remain plain strings.

* *`filepathUri`* -- URI-encoded absolute path to a file on disk.
Encode on write (`FilepathCodec.encode`), decode on read (`FilepathCodec.decode`).
* *`path` / `url`* -- opaque identifier for a resource served by the application.
No encoding required.

`FilepathCodec` keeps text and filesystem decoding separate.
Text accessors decode percent-encoded path bytes strictly as UTF-8 so malformed persisted text fails
loudly.
Path decoding delegates URI conversion to the filesystem provider, preserving POSIX filename bytes
without first converting the path through `Path.toString()` and `sun.jnu.encoding`.
Hierarchical URI values are accepted only when their scheme belongs to an installed filesystem
provider and are decoded through that provider. Local `file:` URIs with an authority are rejected
because local filesystem providers cannot resolve them. Unsupported schemes fail rather than being
interpreted differently by the text and filesystem views. Scheme-less paths, Windows drive paths,
and opaque URIs are rejected so every `filepathUri` value has one unambiguous representation.

== Consequences

* Frontend consumers parse every filepath field the same way (standard URI decoding).
* Non-ASCII filenames round-trip safely through the database and GraphQL schema.
* Raw library paths are encoded before persistence, and V036 normalizes rows created before this
  contract. `FilepathCodec` does not retain a runtime fallback for raw persisted paths.
* `file://` URIs resolve correctly against Jimfs via the `decodeUri` path-extraction fallback, and
  tests use production-like URIs.

= Device Pairing Golden Fixtures v1

Normative payload shapes for `/api/auth/device/**` and the `/api/auth/status` extension, described in `docs/device-pairing-contract.adoc`.

These files are the contract, not illustrations.
`DeviceAuthContractIT` asserts real controller responses against them, so changing a file here is an explicit contract change clients must be told about.

Values in angle brackets are placeholders: *field names and JSON types* are pinned, values vary per request.
Every other value is literal and asserted byte-for-byte — in particular every error body, and the exact lowercase poll codes.

|===
| File | Pins

| `status.json` | Both required booleans on the bootstrap endpoint.
| `code-success.json` | Issuance: opaque device code, grouped user code, absolute URI, server-chosen timings.
| `token-success.json` | A won poll: the standard tokens response.
| `lookup-success.json` | What the approver sees before committing. Never reveals `deviceCode`.
| `decision-success.json` | The *actual* outcome, echoed.
| `authorization-pending-error.json` | The normal every-poll response. HTTP 400, lowercase code.
| `slow-down-error.json` | Polled too soon. HTTP 400.
| `expired-token-error.json` | Unknown, expired, consumed, or race-lost. HTTP 400.
| `access-denied-error.json` | Denied. HTTP 400 — never 403.
| `not-configured-error.json` | HTTP 503 when no canonical base URL is configured.
| `invalid-user-code-error.json` | HTTP 400, malformed after normalization.
| `invalid-decision-error.json` | HTTP 400, validated before any code lookup.
| `not-found-error.json` | HTTP 404, unknown *or expired*, on lookup.
| `expired-error.json` | HTTP 400 on decision only — the approver gets the precise answer.
| `not-pending-error.json` | HTTP 409 on decision only; lookup never 409s.
| `too-many-attempts-error.json` | HTTP 429, always with `Retry-After`.
|===

= Server Endpoint Canonicalization v1

A *client-side* contract. Clients re-normalize every URL they receive — typed by a person, read from a discovery TXT record, or restored from storage — and bind stored credentials to the normalized result rather than to the string they were given.

The server does not implement this table. `STREAMARR_BASE_URL` gets a light validation check at startup (absolute http(s), no userinfo, query, fragment, or percent-encoding, single trailing-slash normalization); full-table conformance on the server would be a second implementation with no consumer.

== Three distinct layers

These are different rules and must not be merged:

. *Manual-input preprocessing* — client UI convenience only. When a person types a host with no scheme into a connection screen, the client may prepend `https://` **before** canonicalization. Not part of this table, and never applied to a discovered `baseurl`.
. *Canonicalization* — this table. Accepts **only absolute** URLs. No scheme inference. v1 rejects percent-encoded input outright rather than specifying decode and re-encode rules.
. *Server configuration* — `STREAMARR_BASE_URL` must already be absolute. A scheme-less value fails startup; silently assuming `https://` would mask an operator typo in the one value every client contract hangs off.

== Normalized form

`{scheme, host, effectivePort, basePath}`:

* `scheme` lowercased; only `http` and `https` are accepted.
* `host` lowercased; IPv6 literals keep their brackets.
* `effectivePort` is the explicit port, or 443 for `https` and 80 for `http`. `https://h:443` and `https://h` are the *same* endpoint.
* `basePath` has its trailing slash removed; an empty path normalizes to `""`.

Two inputs are the same endpoint when all four fields match.
`normalization.json` is the test vector table.

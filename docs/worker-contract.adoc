= Published worker contract

The server owns `src/main/protobuf` and publishes it as `buf.build/streamarr/transcode`.
The worker consumes generated Java stubs from the Buf Schema Registry.
No engine artifact or copy of the proto is needed by the consumer.

== Publication

`.github/workflows/buf-publish.yml` runs after a push to `main` in `streamarr/streamarr-server`.
It uses the repository's `BUF_TOKEN` Actions secret to publish the named module.
The module must already exist and the token must have publication access.
The workflow does not create a registry module or change its visibility.

Pull requests retain the existing format, lint, contract policy and breaking-change checks against their base commit.
They cannot run the publication job.
The publication workflow uses read-only GitHub permissions and does not cancel a running publication when another commit reaches `main`.

After publication, the verifier resolves the registry's `main` label to an immutable commit.
It compares that commit's descriptors with the checked-out contract before resolving a generated SDK.
A mismatch fails verification.
It then compiles `.github/buf-consumer` as a separate Maven project with no server parent or local proto sources.

A successful run uploads `worker-contract-pin-<git-sha>` containing `buf-consumer-pin.properties`.
That file records the module, immutable registry commit and exact generated gRPC SDK version that compiled successfully.
Use this artifact as the source of the worker's dependency pin.

== Java dependency

The Maven repository is `https://buf.build/gen/maven`.
The dependency is `build.buf.gen:streamarr_transcode_grpc_java`.
Its generated POM brings in the matching Protobuf SDK and required runtime libraries.

The SDK version contains the generator version, generator revision, registry commit timestamp and shortened commit ID.
Commit the complete resolved version in the worker's `pom.xml`.
Do not use a moving label, version range or `LATEST` as the worker dependency.
The verifier currently selects the gRPC Java generator at `v1.84.0`, matching the server's gRPC version.

To verify a published contract from a matching server checkout, run:

[source,shell]
----
bash .github/scripts/verify-buf-consumer.sh
----

This requires Java 25, Buf and jq.
Public SDK downloads do not require Maven credentials.
For a private module, authenticate the Buf CLI and provide `BUF_TOKEN` in the environment.
The verifier then uses `.github/buf-consumer/settings.xml`, which supplies a Bearer header from the environment.
The token is never written to the dependency pin or passed as a Maven command-line value.
The publication workflow supplies the same repository secret for this step.

== Extraction prerequisite

The publication workflow can land before the probe operation.
The worker extraction must use a verified published revision that includes the probe messages and supported probe-version capability from ADR 0033.
A passing workflow for the earlier transcode-only contract does not satisfy that requirement.
The worker repository owns its exact dependency pin and verifies it through its standalone tests.

Registry ownership and credentials are tracked in https://github.com/streamarr/streamarr-transcode-worker/issues/2[worker bootstrap].
See https://buf.build/docs/bsr/generated-sdks/maven/[Buf's Maven SDK documentation] for the generated coordinates and authentication contract.
